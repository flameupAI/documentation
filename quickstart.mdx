## Quick Start

Three calls and a check. By the end you will have a person in your workspace, an
event attached to them, and proof it arrived.

<Callout kind="info">**Prerequisites**: a Flameup account. Sign up at [app.flameup.ai](https://app.flameup.ai) if you have not already.</Callout>

## Step 1: Create an API key

<Steps>
  <Step title="Open API Keys" icon="key">
    In the dashboard, go to **Settings → API Keys** and click **Create API Key**.
  </Step>
  <Step title="Say where the key will be used" icon="server">
    Choose **On my server** for this guide, and tick `events:write`,
    `people:write` and `events:read`.

    If you are integrating a mobile app or a website instead, choose **In my app
    or website** — there is nothing to tick, and the key you get is safe to ship
    in your bundle.
  </Step>
  <Step title="Copy it now" icon="copy">
    The key is shown once. It looks like
    `ws_live_abc12345_abc123.a1b2c3…` — the part before the dot identifies it,
    the part after is the secret.
  </Step>
</Steps>

<Callout kind="warning">Keys carry a `live` or `test` label, but **the label does not separate your data** — both write to the same workspace. There is no sandbox today, so treat anything you send as real.</Callout>

The workspace is derived from the key, so it never appears in a URL or a body.

## Step 2: Identify a person

`POST /identify` creates or updates one person, keyed on **your own** user id —
whatever your database already calls them.

<CodeGroup>
```javascript
const API_KEY = 'ws_live_abc12345_abc123.your_secret_here';
const BASE_URL = 'https://api.flameup.ai/api/v1';

const headers = {
  'Content-Type': 'application/json',
  'Authorization': `Bearer ${API_KEY}`
};

await fetch(`${BASE_URL}/identify`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    userId: 'user_12345',
    email: 'jane@example.com',
    traits: { first_name: 'Jane', plan: 'premium' }
  })
});
```

```python
import requests

API_KEY = 'ws_live_abc12345_abc123.your_secret_here'
BASE_URL = 'https://api.flameup.ai/api/v1'
headers = {'Authorization': f'Bearer {API_KEY}'}

requests.post(f'{BASE_URL}/identify', headers=headers, json={
    'userId': 'user_12345',
    'email': 'jane@example.com',
    'traits': {'first_name': 'Jane', 'plan': 'premium'}
})
```

```bash
curl -X POST https://api.flameup.ai/api/v1/identify \
  -H "Authorization: Bearer ws_live_abc12345_abc123.your_secret_here" \
  -H 'Content-Type: application/json' \
  -d '{
    "userId": "user_12345",
    "email": "jane@example.com",
    "traits": { "first_name": "Jane", "plan": "premium" }
  }'
```
</CodeGroup>

Traits are merged, not replaced — send only what changed. Call this again
whenever a trait changes; journeys re-read traits at every decision point, so an
updated trait re-routes a person mid-flight.

## Step 3: Track an event

`POST /track` records something the person did. **This is what campaigns trigger
on.**

<CodeGroup>
```javascript
await fetch(`${BASE_URL}/track`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    userId: 'user_12345',
    event: 'purchase_completed',
    parameters: { amount: 49.99, currency: 'USD', plan: 'premium' }
  })
});
```

```python
requests.post(f'{BASE_URL}/track', headers=headers, json={
    'userId': 'user_12345',
    'event': 'purchase_completed',
    'parameters': {'amount': 49.99, 'currency': 'USD', 'plan': 'premium'}
})
```

```bash
curl -X POST https://api.flameup.ai/api/v1/track \
  -H "Authorization: Bearer ws_live_abc12345_abc123.your_secret_here" \
  -H 'Content-Type: application/json' \
  -d '{
    "userId": "user_12345",
    "event": "purchase_completed",
    "parameters": { "amount": 49.99, "currency": "USD" }
  }'
```
</CodeGroup>

<Callout kind="tip">You do not have to identify someone before tracking them. `/track` creates the person if the id is new, and says `"person_created": true` when it did — which is how you catch a mistyped identifier rather than discovering it weeks later.</Callout>

Campaign triggers match the event name **exactly**, so pick names you are willing
to keep. `object_action` in snake_case is the usual convention:
`purchase_completed`, `trial_started`.

## Step 4: Check it arrived

Read the events back for that person:

```bash
curl "https://api.flameup.ai/api/v1/people/user_12345/events" \
  -H "Authorization: Bearer ws_live_abc12345_abc123.your_secret_here"
```

```json
{
  "success": true,
  "person_id": "7881c966-ab64-4c36-adc9-3fa0359c0e9a",
  "events": [
    {
      "id": "80c2a0d3-dd72-4fde-9dfc-c0b76dd3e42d",
      "type": "purchase_completed",
      "parameters": { "amount": 49.99, "currency": "USD" },
      "created_at": "2026-01-15T10:30:00Z"
    }
  ],
  "total": 1
}
```

You can also open **People** in the dashboard and find `user_12345` there.

<Callout kind="warning">A `403` here means the key is missing `events:read` — the read scope is separate from the write one on purpose. Add it in Settings → API Keys.</Callout>
