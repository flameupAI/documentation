## Welcome to Flameup

Flameup is a powerful customer engagement platform that enables you to understand your users, track their behavior, and communicate with them through personalized messaging campaigns. Whether you're sending transactional notifications, running automated campaigns, or analyzing user behavior, Flameup provides the tools you need.

## What Can You Build?

Flameup provides a complete toolkit for customer engagement:

<Tabs>
  <Tab title="Track Users" icon="users">
    **People API** - Create and manage user profiles with rich attributes.

    - Identify users with custom IDs or email addresses
    - Store user attributes and preferences
    - Segment users based on behavior and properties
    - Batch operations for efficient bulk updates

    <Callout kind="info">The People API supports upsert operations, making it easy to create or update users in a single call.</Callout>
  </Tab>
  <Tab title="Track Events" icon="activity">
    **Events API** - Capture user actions and behaviors in real-time.

    - Track page views, clicks, purchases, and custom events
    - Attach rich properties to every event
    - Query event history for analytics
    - Trigger campaigns based on user actions
  </Tab>
  <Tab title="Send Messages" icon="mail">
    **Messaging APIs** - Reach users through push notifications.

    - **Campaigns**: Automated messages triggered by events or schedules
    - **Messaging APIs**: Push notifications and emails for confirmations, alerts, and updates
    - **Push Notifications**: iOS and Android push support (Web coming soon)
  </Tab>
</Tabs>

## Core Concepts

Understanding these key concepts will help you get the most out of Flameup:

<ExpandableGroup>
  <Expandable title="Workspaces" default-open="true">
    Workspaces are isolated environments for your data. Each workspace has its own:

    - Users (People)
    - Events
    - Campaigns
    - API Keys

    Use separate workspaces for development, staging, and production environments.
  </Expandable>
  <Expandable title="API Keys" default-open="false">
    API keys authenticate your requests and determine what actions you can perform.

    - **Format**: `ws_live_{workspace}_{random}.{secret}`
    - **Permissions**: Granular control over read/write access

    See the [Authentication](/authentication) guide for details.
  </Expandable>
  <Expandable title="People & Events" default-open="false">
    **People** represent your users. Each person has:
    - A unique identifier (external_id)
    - Contact information (email, phone)
    - Custom attributes

    **Events** represent user actions. Each event has:
    - An event name (e.g., "purchase_completed")
    - Properties (e.g., order_id, amount)
    - Timestamp
    - Associated person
  </Expandable>
</ExpandableGroup>

## Base URL

All API requests should be made to:

```
https://api.flameup.ai/api/v1
```

Workspace-scoped endpoints follow this pattern:

```
https://api.flameup.ai/api/v1/workspaces/{workspace_id}/{resource}
```

## Quick Example

Two calls: describe a person, then record something they did. The workspace comes
from the key, so it never appears in the URL or the body.

<CodeGroup>
```javascript
const API_KEY = 'ws_live_abc12345_abc123.your_secret_here';
const BASE_URL = 'https://api.flameup.ai/api/v1';

const headers = {
  'Content-Type': 'application/json',
  'Authorization': `Bearer ${API_KEY}`
};

// 1. Identify — creates or updates the person, keyed on your own user id
await fetch(`${BASE_URL}/identify`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    userId: 'user_123',
    email: 'jane@example.com',
    traits: { first_name: 'Jane', plan: 'premium' }
  })
});

// 2. Track — this is what campaigns trigger on
await fetch(`${BASE_URL}/track`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    userId: 'user_123',
    event: 'signed_up',
    parameters: { source: 'organic' }
  })
});
```

```python
import requests

API_KEY = 'ws_live_abc12345_abc123.your_secret_here'
BASE_URL = 'https://api.flameup.ai/api/v1'
headers = {'Authorization': f'Bearer {API_KEY}'}

# 1. Identify
requests.post(f'{BASE_URL}/identify', headers=headers, json={
    'userId': 'user_123',
    'email': 'jane@example.com',
    'traits': {'first_name': 'Jane', 'plan': 'premium'}
})

# 2. Track
requests.post(f'{BASE_URL}/track', headers=headers, json={
    'userId': 'user_123',
    'event': 'signed_up',
    'parameters': {'source': 'organic'}
})
```

```bash
curl -X POST https://api.flameup.ai/api/v1/identify \
  -H "Authorization: Bearer ws_live_abc12345_abc123.your_secret_here" \
  -H 'Content-Type: application/json' \
  -d '{"userId":"user_123","email":"jane@example.com","traits":{"first_name":"Jane","plan":"premium"}}'

curl -X POST https://api.flameup.ai/api/v1/track \
  -H "Authorization: Bearer ws_live_abc12345_abc123.your_secret_here" \
  -H 'Content-Type: application/json' \
  -d '{"userId":"user_123","event":"signed_up","parameters":{"source":"organic"}}'
```
</CodeGroup>

<Callout kind="tip">`/track` creates the person if it has not seen that id, so the order does not matter and there is no first-event race. The response says `"person_created": true` when it did — useful for catching a mistyped identifier.</Callout>

## Health

| Endpoint | Purpose |
|---|---|
| `GET /health` | Liveness. Returns `{status: "alive"}` |
| `GET /api/v1/health` | Readiness, with per-service status for the database and event store |

Neither requires authentication, and neither counts against your rate limit.
